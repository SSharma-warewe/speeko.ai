# LiveKit voice-worker instructions

Scope: `apps/worker`. Inherit the [root instructions](../../AGENTS.md). This is a stateless LiveKit Agents server, not a Nest app. API owns Postgres, SIP dial/queue, tenant credentials, and durable call rows.

## Runtime and metadata

- `human_transcription` jobs branch before the AI metadata parser and use `session/human-transcription-job`. They never build an AgentSession/LLM/TTS/tools or publish audio/data. Start authenticates with API and retrieves the persisted browser/SIP identities plus a private callback token; no database/provider credentials enter metadata. Connect without auto-subscription, subscribe only to those identities' audio (caller microphone only), wait for SIP answer, then capture separate 16 kHz mono streams through the existing Python Sarvam sidecar. Human settings are auto language, balanced stream, codemix finals; AI defaults are unchanged.
- Human capture handles mute/republication/reconnect without duplicate readers, drains replaced streams, and does not reconnect failed Sarvam sessions. Persist only final text with stable segment UUIDs and caller/contact timestamps via dedicated start/checkpoint/finish callbacks; interim text never becomes a final. Five-second heartbeats carry cumulative measured provider seconds and observed listener duration. Callback retries use two-second requests/three attempts. Pending finals are bounded to 1,000, payload batches to ten, utterances to 8,000 characters; truncation/exhaustion marks partial. Drain at hang-up is limited to five seconds. Missing keys, provider/drain errors and unexpected listener shutdown mark partial/unavailable and never terminate the human room or phone leg.
- Human transcript tests: `src/test/session/human-transcription-job.spec.ts`, `src/test/agent.entry.spec.ts`, and Sarvam adapter suites. Deploy this compatible listener and sidecar before an API that dispatches the new mode.

- `ttsCacheEnabled` is an optional API-resolved job boolean. `JobMeta` accepts only literal true; legacy/missing/null/malformed values and fallback metadata are off. Inbound live refresh replaces stale dispatch policy. `AgentRuntimeBuilder` constructs local runtime/shared client only when true and pipeline; otherwise generated parent/task speech uses ordinary SDK synthesis. The independent prepared-sentence policy below can still create a finite-speech runtime. A runtime retains its startup policy. API live shared authorization may revoke further access; disposal never closes the session provider.

- `src/main.ts` registers the explicit `LIVEKIT_AGENT_NAME` (default `call-agent`); `src/agent.ts` handles jobs. One dispatch name supports both directions.
- Canonical [AgentJobMetadata](../../packages/contracts/src/job-metadata.ts) carries ids, direction/medium, task, persona/hooks, enabled tool ids, context, participant identity, and optional voice/model/STT/TTS/language/rate/delivery settings. Metadata is data, never executable code/tool schemas or provider secrets.
- Flow: parse metadata → inbound live refresh → participant/lifecycle gates → `AgentRuntimeBuilder` → model/prompt/tool/task/voice builders → AgentSession. Build from shared catalog specs; do not add a local catalog or DB lookup.
- Null catalog fields use shared Gemma/Inworld/Deepgram defaults; null hooks use defaults, empty hooks skip speech. BYO plugin choices fail if their worker key is absent; do not silently fall back.
- Inbound SIP metadata has no unique callId. Re-fetch current org-agent pack via `/api/internal/organization-agents/:id/job-metadata`, ensure the room's call via `/api/internal/calls/inbound`, and use returned id for tools/completion. Voice/persona changes apply without republishing.
- Outbound SIP must wait for answer before constructing full models/provider sessions or starting speech. Inbound ringing must start immediately after ensure; waiting for active first deadlocks answer. API creates SIP participants; worker never dials.

## Persona, tasks, tools, and speech

- Persona describes identity/tone/policies. Tasks own workflow/completion; tools own executable capabilities. Use `composeTaskInstructions` so persona survives `AgentTask.run()` replacing the parent.
- `builders/` constructs runtime; `tasks/` holds workflow; `tools/` implementations; `speech/` live talk/cache/hangup; `session/` metadata/SIP/shutdown lifecycle; `callbacks/` API transport; `sarvam/` adapters; `common/` shared helpers.
- Tasks use registry keys from contracts and `createWorkflowTask`; tools use registry ids from contracts and ToolRegistry. Always include endCall. Do not load implementations from Postgres or grant tools beyond metadata.
- Pipeline parent onEnter greets, then task runs; parent onExit speaks the closing verbatim. Native realtime task onEnter generates the opening after handoff, and task completion generates/waits for goodbye before complete. Parent speech APIs cannot stand in for realtime playout.
- Task results alone never prove completion. Set `taskCompleted` only after task.run resolves. Preserve explicit evidence gates, do-not-re-greet rules, question/completion separation, Hindi Devanagari handling, and workflow-specific required fields.
- Keep pipeline cloud TurnDetector v1 + bundled Silero, endpointing/cache behavior, realtime VAD choices, and Sarvam REST versus realtime paths aligned with [runtime reference](docs/runtime.md). Read that reference before speech changes; it records provider-specific traps and timing invariants.
- Enabled pipeline speech uses one disposable job-local `speech/tts-cache-runtime` shared by parent/task `cached-tts-node` hooks and finite `sayCached` helpers. Generated Inworld/Fish/OpenAI/Sarvam speech captures the original SDK synthesis at existing sentence boundaries; generated xAI word streaming, expressive speech, changed providers, and native speech-to-speech bypass caching. Automatic caching introduces no startup warmup. Independently enabled prepared sentences use bounded parallel synthesis after session entry, described below. Finite Inworld/Fish use `stream()` plus closed `updateInputStream` input; OpenAI/xAI/Sarvam keep supported `synthesize()` (Sarvam finite phrases use REST even with Bulbul realtime selected). Session retains the original provider. Close streams, never the borrowed provider. See [TTS cache integration plan](docs/tts-cache-integration-plan.md) for identity, limits, verification, and shared-storage/UI follow-ups.
- Cache identities hash tenant scope plus the resolved construction settings, transport/format/transform revisions and exact text. Missing org scope gets an ephemeral random scope. Cache owns PCM copies and safe alignment metadata; replay uses fresh frames and rebased timings. Only successful, complete, nonempty audio commits; SDK terminal error events conservatively invalidate concurrent captures. Defaults: 16 MiB accounted committed bytes, 10-minute TTL/LRU, 1 MiB / 15-second clips, 4 MiB concurrent capture, current plus one lookahead. First valid publication wins. Dispose on session close/job shutdown/build/start failure. Cache failures must not restart speech. Counters track local source invocations, not upstream retries or billing savings; preserve normal SDK metrics. Either saved policy may create this runtime; generated hooks require automatic caching. Both policies default off.
- Optional `tts-shared-cache-client` uses API-authorized Postgres storage through existing API_BASE_URL/WORKER_CALLBACK_SECRET, never worker SQL. `TTS_SHARED_CACHE_ENABLED=false` defaults off; API separately enforces its tenant UUID allowlist. Construction receives the actual room name beside metadata and enables sharing only with a valid persisted call/tenant scope. Native realtime has no shared client; missing scope/config stays local. Automatic caching introduces no startup lookup/warmup; optional prepared sentences perform background finite lookups after entry.
- Local fill waiting and complete shared lookup/validation share one 25 ms budget. Expired/corrupt/wrong-format/late hits fall back to one live source; imported expiry is min(local TTL, server expiry). Complete original captures enqueue publication off playback: two active uploads, at most 4 MiB reserved queue/in-flight bytes, one-second requests, no retry or shutdown drain. Cancellation/disposal aborts lookups/uploads and releases buffers; session providers remain borrowed. Three transport/server failures back off ten seconds; 401/404 disable sharing for the job; 403 disables the denied purpose only. Revision-1 PCM s16le envelopes contain only ordered frame boundaries/safe alignment, SHA-256 and format/duration; shared namespace is `shared-v1-livekit-1.7.1`. Safe alignments/audio may contain personal information; logs contain aggregate counters only. API reuse expiry is 24 hours; physical cleanup/WAL/backups follow API guidance. See [API shared-cache authority](../api/AGENTS.md#shared-tts-cache) for budgets, schema and release prerequisites.
- API-proxied calendar tools use call id and worker secret. GHL free slots contain no existing appointments; booking requires contact id. No org Meta/GHL/Nylas secrets enter metadata or this worker.

## Prepared sentences

For pipeline jobs with `ttsPreparedSpeechEnabled=true`, a nonempty configured `prompt.onEnterInstructions` is now exact opening text: parent `onEnter` calls `sayCached` without an opening LLM request. Task-defined sentence/silent openings retain precedence; task `agent` mode uses the configured opening. Null/missing/blank selects the generated default; explicit empty remains silent. Preparation Off and native realtime preserve generated-opening semantics. Register eligible exact opening text before playback, exclude it from the entire speculative queue (including matching closing/filler text), and abort its finite capture when playout finishes/fails. The existing answer gate, shared 25 ms lookup deadline, provider/settings/tenant identities and bounded audio limits remain unchanged. Both resolved policies and sharing flags remain independent.

Generated-speech provider identity must use `ctx.agent.getActivityOrThrow().tts`, matching the SDK default synthesis path. LiveKit 1.7.1's hook `ctx.tts` exposes only the agent override, so it is undefined when the provider is inherited from AgentSession. Comparing that value with the cache provider incorrectly bypasses every generated opening/reply. Keep actual provider changes, explicit null and text-only sessions excluded. Regression coverage uses real parent/task SDK hook contexts with inherited providers.

- Optional resolved job boolean ttsPreparedSpeechEnabled enables exact finite speech independently of ttsCacheEnabled. Only literal true enables it; missing/malformed/fallback metadata stays off. Native speech-to-speech remains unsupported.
- speech/prepared-sentences selects the existing legacy inbound questions/clarifications, outbound demo fillers and verbatim closing, deduplicated by exact text. Configured tasks contribute explicitly configured saved speech plus eligible closing text; prompts and generated questions are not converted into recordings.
- Parent onEnter starts preparation alongside opening without awaiting it or gating session.start. Outbound answer gating is unchanged; inbound pickup never waits. Two consumers share the job runtime, finite adapters, local identity/storage/capture limits and one shared client's upload budget.
- Each preparation has a 10-second deadline; the queue stops at 30 seconds or shutdown. Playback waits at most the existing combined 25 ms budget, then cancels matching speculative synthesis before starting live synthesis. Background work never duplicates a foreground fill. Errors/oversized clips stop speculative capture and cannot fail the call.
- Shared requests carry purpose automatic/prepared; missing purpose remains automatic for legacy clients. API independently rechecks the corresponding live preference with the same tenant/room/model/allowlist restrictions. A 403 disables only that purpose; 401/404 disable the client. Identities and storage are shared, so matching agents in the same organization reuse recordings.
- With automatic caching off, finite audio is eligible only for listed prepared text; generated hooks are absent. Local prepared entries are released after completed/cancelled playback. With automatic caching on, existing TTL/LRU retention applies. One unref'ed 30-second timer sweeps expired local entries.
- beginShutdown cancels preparation/uploads while retaining local closing audio during drain. Session close, job shutdown and build/start failure dispose the runtime idempotently: abort sources/readers, clear queue and buffers, resolve waits, clear timer/listeners, reject late publication. The borrowed session provider is never closed by the cache. Cancellation races stalled provider iteration so runtime listeners are released even when SDK close does not finish iteration.
- Verification includes parallel limits, deadlines, foreground races, shared hits, independent policies, repeated cleanup and local expiry. Provider mocks do not establish real ringing/latency/RSS behavior; live acceptance remains required.
- Local implementation verification on 2026-10-08 passed the affected worker/API/portal regression suites, hangup drain and oversized-capture checks, plus 15 real PostgreSQL storage/HTTP cases using a disposable native PostgreSQL 17 fixture at the guarded test address. The fixture was stopped afterward. API/worker/portal builds, contracts/portal typechecks and diff checks passed. Canonical model synchronization, production deployment and live acceptance are still pending.

## Callback response semantics

- LiveKit 1.7.1 duplicates REST TTS usage between ChunkedStream and StreamAdapterWrapper. `speech/tts-usage` keeps the original provider instance and suppresses only redundant streamed metrics when that provider declares `streaming: false`. Underlying request metrics, tokens, partial/error usage, native streaming and independent requests remain intact. Applied during model construction whether caching is enabled or disabled; revisit against real SDK regression tests on upgrades.
- Enabled runtime disposal logs one bounded aggregate `tts-cache` record. `cacheWaitMs` covers local lookup/fill/shared lookup plus validation; `segmentToFirstFrameMs` covers cache stream creation through its first yielded frame, including lookahead/consumer scheduling. Disjoint histogram buckets have upper bounds in `boundsMs`, with a final overflow bucket. Neither measures caller-audible end-to-end latency. No speech, PCM, alignment or provider request IDs are added to these diagnostics.

- Shutdown sends rCompleteCallPayload](../../packages/contracts/src/worker-callback.ts) to `/api/internal/calls/:id/complete`: status, timestamps, transcript, usage/session report, taskResult, taskCompleted, and sanitized tool events as applicable.
- Unanswered SIP → failed/no_answer; answered + taskCompleted → completed; answered without completion → API incomplete. Declined/not-booked completed workflows remain completed. Do not invent answeredAt or infer status from result JSON.
- Callback transport has per-attempt timeout and bounded retry for 408/429/5xx/network/abort; exhaustion never throws past shutdown. API terminal handling is idempotent and ignores late pending/creating completion; sweeper is last-resort recovery.
- Ephemeral process/session state is allowed; durable authority remains in API. Never log provider keys, worker secrets, or unsanitized sensitive tool values.

## Detailed runtime

### Job metadata shape (API → worker)

Canonical TypeScript type: `AgentJobMetadata` in `@call-agent/contracts`. Inbound SIP dispatch omits `callId` (static at publish) and includes `organizationAgentId`.

The [API metadata example](../api/docs/architecture.md#job-metadata-shape-api--worker) documents the wire fields. Use [AgentJobMetadata](../../packages/contracts/src/job-metadata.ts) for the authoritative type; do not duplicate it locally.

Catalog examples below are explanatory snapshots; current supported ids/defaults come from rcontracts](../../packages/contracts/AGENTS.md). `model` is the **LLM / realtime** catalog id (`google/gemma-4-31b-it`, `openai/gpt-4.1-mini`, `openai/gpt-5.6-luna-fast`, `xai/grok-4.6`, `openai/gpt-realtime-2.1-mini`, `xai/grok-voice-think-fast-2.0`; `null` = Gemma via LiveKit Inference). **Luna Fast** is pipeline GPT-5.6 (`gpt-5.6-luna`) with OpenAI `service_tier=fast` and `reasoning.effort=none` (not speech-to-speech). Realtime ids run speech-to-speech (no STT/TTS; the realtime API owns VAD). `ttsModel` is the **speech** catalog id (`inworld/inworld-tts-2`, `fishaudio/s2.1-pro-free`, `openai/gpt-4o-mini-tts`, `xai/tts-1`, `sarvam/bulbul-v3`, `sarvam/bulbul-v3-realtime`; `null` = Inworld) and is ignored on realtime jobs. `sttModel` is the **STT** catalog id (`deepgram/nova-3`, `sarvam/saaras-v3`, `sarvam/saaras-v3-realtime`; `null` = Deepgram) and is ignored on realtime jobs. `speechLanguage` is a BCP-47 code for Sarvam STT/TTS (`hi-IN`, `en-IN`, `unknown`, …; `null` = worker default: Hindi persona → `hi-IN` for TTS **and STT**, else TTS `en-IN` / STT `unknown`; realtime STT maps remaining `unknown` → `auto`). Switching `ttsModel` (or a realtime `model`) changes the allowed `voice` set (catalogs in `@call-agent/contracts` `tts.ts` / `llm.ts` / `stt.ts`). Inworld + Fish + Deepgram stay on LiveKit Inference. `temperature` is **LLM** reply randomness (not used on native realtime). `speakingRate` maps to Inworld `speaking_rate`, Fish/OpenAI/Grok `speed`, or Sarvam `pace`; `deliveryMode` is Inworld-only. BYO OpenAI/xAI usage is billed by those providers and is **not** on the LiveKit list-price call snapshot. LiveKit plan discounts do not apply to those lines.

Outbound: `POST /api/admin/calls/outbound` (and user enqueue / dial / integration) accepts optional `task` or `voiceTaskId`. Configured defaults resolve from the org agent and then platform template; legacy task keys retain their previous fallback. Inbound metadata refresh resolves the saved default and persists its exact published version during ensure.

### LiveKit worker

- Entry: `apps/worker/src/main.ts` → `cli.runApp` with `agentName` = `LIVEKIT_AGENT_NAME` (default `call-agent`) and `numIdleProcesses` from `LIVEKIT_NUM_IDLE_PROCESSES` (default `1`) to limit idle RAM on small hosts.
- Job entry: `apps/worker/src/agent.ts` parses metadata → **inbound + `organizationAgentId` re-fetches live pack** → `new AgentRuntimeBuilder(meta).build()` (builders) → voice-only `AgentSession`.

### Layout

`builders/` constructs LiveKit objects from metadata (agent / model / prompt / voice / task / tool + realtime model wrappers). `speech/` is live-session talk (`tts-cache`, `demo-tool-filler`, `realtime-speech`, `hangup`). `session/` is job/room lifecycle (`job-metadata`, `sip-answer`, `shutdown-status`). `tasks/` is workflow (`workflow-task`, `inbound-service-tracks`, `demo-booking-tracks`, `demo-booking-crm`, `*.task.ts`). `tools/`, `callbacks/`, `sarvam/`, `common/` stay one concern each. Specs live under `src/test/<same-folder>/`.

### Workflow / speech

`tasks/workflow-task` wraps `AgentTask.create`: realtime **task `onEnter` `generateReply`s the opening** after handoff; inbound script may cache location → timing → BHK/budget via `session.say` + `StopResponse` on task `onUserTurnCompleted`; **outbound `demo_booking` pipeline** caches good-time yes → “when works” and busy/callback via the same hook (declined and real datetimes stay with the LLM); skip realtime, `finishWorkflowTask` goodbyes on the task then `complete()`.

### Turn detection / memory

Pipeline (Deepgram **and** Sarvam realtime STT) uses `inference.TurnDetector({ version: 'v1' })` (cloud) + bundled Silero. Endpointing is **200 / 400ms** (override SDK streaming 300 / 2500 so fragments do not sit 2.5s). `preemptiveTts: true` so TTS starts during that wait. Sarvam server VAD still endpointing transcripts (FINAL); it does **not** own turn taking (`turnDetection: 'stt'` is not used). Grok realtime uses pinned server VAD (700ms / no interrupt). Main skips registering local EOT (`lk_eot_audio`) so the shared InferenceProcExecutor (~138 MB) is not started. Bundled Silero VAD still auto-provisions in pipeline job processes.

### Tasks

LiveKit `voice.AgentTask` under `apps/worker/src/tasks/*` via `createWorkflowTask`. **Pipeline:** parent **onEnter** speaks opening (configurable), then `task.run()`. **Realtime (Grok Voice / GPT Realtime):** skip parent `generateReply` — `task.run()` replaces the parent and would discard in-flight audio (`waitForPlayout` returns before playout; logs `In-progress generation discarded due to provider abandonment`). The **task `onEnter` `generateReply`s** `buildOpeningInstructions` (`toolChoice: 'none'`) and `waitForRealtimeUtterance` — prompt-only FIRST TURN does not trigger speech. Opening wait is wall-clock **3.5s min** and returns `wait=min` when xAI never reports `speaking` (do not treat already-idle as playout done). `composeTaskInstructions` tells pipeline (and realtime) tasks not to re-greet after the opening, and adds a realtime turn rule (every spoken turn until `complete_*` must end with a question; Hindi personas stay in Devanagari). Task owns workflow + completion tools. Persona is copied into the task system prompt so company facts survive the handoff (`excludeInstructions: true` plus `excludeConfigUpdate` / `excludeHandoff` on copied history so it is not duplicated and realtime plugins do not throw `Unsupported item type: agent_config_update`). Also: never `complete_*` in the same turn as a question. Structured result in `userData.taskResult`. `userData.taskCompleted = true` only after `task.run()` **resolves** (not because `taskResult` is set). `loan_collection` / `personal_loan_outreach` / `real_estate_outreach` **evidence gates** reject `complete_*` on filler/empty last user turns (`Hello.`, `So.`, `A`); `WRONG_PERSON` / `ALREADY_PAID` need an explicit phrase; `PROMISED` still needs `promisedPayDate` + `delayReason` + `helpRequested` (do not complete/hangup on the help question); `WRONG_PERSON` does not inherit the context name. Unclear identity: retry the name question once, then assume the expected contact — do not complete WRONG_PERSON on noise. Hindi personas: ASR **han/haan → English "No."** is treated as yes (`HINDI_HAN_ASR_RULE`); WRONG_PERSON is blocked on a short No.

### Tools

hard-coded in `apps/worker/src/tools/*`; metadata only lists ids. Always includes hangup (`endCall` / `createEndCallTool`).

### Hangup

successful task completion auto-ends the session and deletes the LiveKit room (SIP drops). **Pipeline:** hang up immediately; parent **onExit** `session.say` plays the canned/custom goodbye. **Realtime:** `finishWorkflowTask` `generateReply`s the canned goodbye (`buildRealtimeClosingInstructions`, `toolChoice: 'none'`, never `allowInterruptions: false`) **on the task** before `complete()`, waits (`waitForRealtimeUtterance` — `min` 2.5s / timeout **3.5s**, do **not** trust `waitForPlayout` or xAI `agentState`; Hindi canned line when the persona is Hindi), then parent `hangUpCall`; parent does not `generateReply` goodbye (that ran on a wiped parent context and re-greeted). onExit stays silent (`session.say` does not play on native realtime). Mid-call hangup uses the `end_call` tool. Shared helper: `apps/worker/src/speech/hangup.ts`.

- **Does not dial SIP** — API owns `CreateSIPParticipant`. For `medium=sip`, worker connects and `waitForParticipant` (SIP party joins while still ringing). **Outbound** then **`waitForSipAnswer`** until `sip.callStatus` is `active`/`automation` (or published audio) **before constructing models** (`buildAgentRuntime`) and before `session.start` / opening speech. Realtime S2S (Grok Voice / GPT Realtime) must not open a provider session while the INVITE is in flight. Hangup / disconnect / 60s timeout before answer POSTs `failed` + `no_answer` (retryable). Fire-and-forget CreateSIPParticipant (`waitUntilAnswered=false`, the queue path) must **not** send `ringingTimeout` / `SIPMediaConfig` — extra media fields on the INVITE are enough for Frejun to drop the call without logging it. `waitUntilAnswered=true` still sets **`ringingTimeout=60s`** and **`media.mediaTimeout=90s`**. **Do not auto-pin LiveKit `destinationCountry=in` on +91 dials.** Frejun allowlists US LiveKit SIP egress; India-origin INVITEs never appear in their CDR and come back `USER_UNAVAILABLE` (~30s) while still `dialing`. Set `destinationCountry` only when the provider requires it. Outbound Frejun trunks must use **SIP TCP** (`SIP_TRANSPORT_TCP`); `AUTO` falls through to UDP and Frejun never replies (`0 intermediate responses`, ~34s `USER_UNAVAILABLE`). Job shutdown never reports `completed` unless the callee answered. **Inbound** must **not** wait for `active` — LiveKit keeps inbound at `ringing` until the SIP caller subscribes to remote audio, which only happens after `session.start`. Waiting first deadlocks (caller hears ringing, agent never greets, hangup → `no_answer`). Inbound: ensure the `calls` row, skip `waitForSipAnswer` unless already `hangup`, then `session.start` immediately so LiveKit can 200 OK.

### Inbound SIP tape

dispatch-rule job metadata has no unique `callId`. Before building models, inbound jobs with `organizationAgentId` POST `POST /api/internal/organization-agents/:id/job-metadata` and merge the live persona/tools/voice (so a realtime Voice-tab save is used on the next ring without republish). When `direction=inbound`, `medium=sip`, and `callId` is missing, the worker then POSTs `POST /api/internal/calls/inbound` (upsert by room name + SIP attrs) after the SIP participant is present, then uses the returned id on the existing complete path. Calendar tools need that `userData.callId`.

### Opening / goodbye

**Pipeline:** parent `onEnter` via `buildOpeningInstructions` + `generateReply` (`allowInterruptions: false`, `toolChoice: 'none'` — Deepgram ghosts / callee hello must not chop TTS); **automatic local caching after model construction** (same runtime on parent and task TTS hooks; generated stable segments capture live SDK audio, repeated segments replay; fixed script/filler/goodbye helpers supply a single finite synthesis stream on a miss). **No pre-start warmup gate**; `session.start` follows runtime construction and existing SIP answer gates. Native S2S bypasses the cache; generated xAI word streaming retains its original latency path. Outbound demo check/book tools play that cached filler **overlapped with the HTTP** (`withDemoToolFiller`); GHL lookup/upsert for that task is **background** (`startDemoCrmPrefetch` on enter; `scheduleGhlMeeting` awaits the promise). Do not construct the full runtime (STT / realtime) before outbound answer. Do not launch competing background Sarvam synthesis during the opening; generated capture follows its original SDK stream. `composeTaskInstructions` tells the task not to re-greet; overlapping user audio is kept (`discardAudioIfUninterruptible: false`). Inbound pipeline: list/sell/buy/rent then location (sector 1–88) → timing → BHK/budget may play `session.say({ audio })` + `StopResponse` (no LLM on those turns; one finite TTS source on a miss, replay on a hit). Timing treats Sarvam `हफ्ते`→`वास्ते` as this week; a miss plays a cached clarify line (not the original ask, not the LLM). `onExit` via `buildClosingSpeech` + `session.say` (verbatim canned or custom line; not a second LLM turn). **Realtime:** parent does not greet; task `onEnter` `generateReply`s the same opening; `complete_*` calls `finishWorkflowTask` (goodbye on the task) then hangup (`session.say` skipped). `createEndCallTool` uses `endInstructions: null` so hangup does not double-speak.

- On shutdown, POSTs transcript + usage + **taskResult** + **`taskCompleted`** to `POST /api/internal/calls/:id/complete` when `API_BASE_URL` + `WORKER_CALLBACK_SECRET` are set. Each attempt has an `AbortSignal` timeout (default 8s) and retries up to 5 times on **408 / 429 / 5xx / network / abort** (exponential backoff). **Never throws** after exhaustion so `failedEarly` still reaches `ctx.shutdown`. Duplicate POSTs are idempotent (terminal rows fill missing transcript/usage/cost). Late complete on `pending` / `creating` is ignored so a sweeper requeue is not clobbered. Unanswered SIP → `status=failed` `failureCode=no_answer`. Answered session + `taskCompleted=true` → API `completed`. Answered session without `taskCompleted` (or omitted, conservative) → API `incomplete`. Do **not** invent `answeredAt` on the API when the worker omitted it. `DECLINED` / `NOT_BOOKED` after `complete_*` stay `completed` (workflow finished). `incomplete` is not retried by the dialer. Stale sweeper remains the last-resort safety net if every attempt fails.

## Shutdown wire response

rCompleteCallPayload](../../packages/contracts/src/worker-callback.ts) is the worker-to-API response contract, independent of the dispatch metadata. Session status is completed/failed; taskCompleted tells API whether an answered session maps to completed or incomplete. Payload may include errorMessage/failureCode, answeredAt/endedAt, transcript, usage, sessionReport, taskResult and sanitized toolEvents. Do not turn taskResult existence into taskCompleted or fabricate answeredAt.

rworker-api-client](src/callbacks/worker-api-client.ts) implements timeout/retry; rcall-callbacks](src/callbacks/call-callbacks.ts) implements complete/inbound/live-metadata requests. API uses authenticated internal routes, idempotent terminal completion, and pending/creating late-callback fencing. Runtime objects and memory caches remain job-local; optional shared speech storage uses the separate bounded HTTP client and remains API-owned alongside durable call records and recovery.

## Task/tool addition procedure

1. Add the stable task key or camelCase capability id and exports to contracts; rebuild it first.
2. Implement through createWorkflowTask and TaskRegistry, or tools and ToolRegistry. Keep objective/result/evidence/completion separate from capability execution.
3. Define required context and evidence gates; preserve pipeline/realtime opening/goodbye and copy persona through composeTaskInstructions.
4. Update API validation/metadata, allowlists/profiles and portal choices. A task cannot grant unassigned tools.
5. Test required fields, refusal/noise, interruption/failure, repeat/completion and contract alignment with mocked sessions/providers.
6. Build affected consumers and deploy the appropriate services only. Packers/parsers/callbacks must remain compatible.

WORKER_CALLBACK_SECRET is required on both sides. API_BASE_URL is an origin without /api. CompleteCallPayload carries status, errorMessage/failureCode, answeredAt/endedAt, transcript, usage/sessionReport, taskResult/taskCompleted, and sanitized toolEvents. ## Configurable AgentTask runtime

An AgentJobMetadata.voiceTask snapshot selects tasks/configurable.task.ts before the legacy registry. Schema version 1 accepts only validated declarative objective/phases/context/result/outcome definitions and supported code-owned capability/check IDs. Missing snapshots for custom_* keys and unsupported/invalid snapshots fail explicitly. Unknown legacy keys retain the legacy fallback. Ordered phases guide the model; v1 does not enforce a phase state machine or branching graph.

The worker builds a strict Zod complete_voice_task schema from string/number/boolean/enum result fields and configured outcomes. Outcome-specific and global required fields, usable caller answers and legacy workflow checks gate completion. Missing answers/evidence return an actionable tool error so the conversation can continue. Callback/refusal outcomes do not inherit success-path requirements unless the author marks a field globally required. Persona, clock, no-repeat, Hindi and existing hook semantics are composed with the task. Explicit opening/goodbye hooks still take precedence; default openings use the objective/first phase.

Configured calls bypass the implicit inbound property script and demo CRM prefetch. Legacy factories keep those optimizations. All eligible pipeline parents and tasks share the automatic local TTS cache; configured replies are included. Pipeline/realtime speech behavior and outbound SIP answer gating are preserved. Live inbound org-agent metadata refresh must succeed; stale cached configuration is rejected. A refreshed legacy selection clears an older configured snapshot, and configured context defaults come from the live version.

Real booking evidence is captured before event sanitization from successful scheduleGhlMeeting/createCalendarEvent results with an actual appointment/event ID and normalized provider times. Model-provided IDs, failed tool responses and the booking stub cannot prove booking. Successful duplicate booking attempts reuse the receipt. Pending/uncertain writes are never repeated automatically, including provider failures with unknown outcomes or success responses missing IDs. Successful cancellation clears the matching receipt. Task completion is set only after task.run() resolves; leftover result data remains incomplete.

Runtime/completion diagnostics include task identity/version/outcome and blocked completion, without logging configured result/context payloads or tool summaries. Full sanitized tool events remain on the authenticated call record for operations. Focused tests: src/test/tasks/configurable.spec.ts, session/job-metadata.spec.ts, agent.entry.spec.ts and API configured dispatch tests. Live audio/voice-provider and real-calendar smoke tests require a connected worker and upstreams; mocked tests do not establish voice quality.

## Task-managed saved speech

- Configured voice-task snapshots may contain savedSpeech and phase sentenceKeys. Pipeline configurable tasks expose one internal speak_saved_sentence tool constrained to snapshot keys; it is not a business capability or an API call. Text comes from the pinned task snapshot. Native speech-to-speech compiles wording guidance without exposing this playback tool or preparing audio.
- The call-owned saved-speech state serializes playback, reserves tool-call IDs once (bounded to 256), waits for each distinct say handle, and returns undefined so the installed LiveKit SDK does not generate a post-tool reply. At most one saved sentence is accepted per caller turn. A pipeline llmNode guard streams saved keys immediately but holds completion until the model step ends, suppressing completion if that step requested saved speech in either order. Completion also waits for a usable caller response and checks the SDK speech handle. Playback never establishes task success or external-write evidence.
- Cache capture receives an abort signal. Tool cancellation, hangup, session close, startup failure, and job shutdown interrupt speech, abort capture, release queued work and remove listeners; disposal is idempotent. The session-owned provider remains borrowed.
- Task opening/closing selections override agent hooks only when explicitly set to sentence/silent; omitted/agent selections preserve existing defaults. Pipeline exact opening uses sayCached before background preparation is scheduled. Selected opening audio is eligible for foreground cache lookup but excluded from speculative preparation to avoid competition. Closing follows the normal drain path.
- Prepared sentences selects eligible task text in UI order, deduplicated by exact text, and preserves legacy selection for unconverted jobs. Per-sentence prepare=false skips background work while playback and ordinary automatic caching remain available. Existing preparation limits, identity, tenant authorization, sharing budgets, expiry and cleanup are unchanged.
