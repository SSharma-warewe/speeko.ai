# Speech cache live acceptance

The user will run live calls after the authorized deployment. Local automated tests establish SDK accounting and deadline behavior, not live provider billing or caller latency. Shared caching remains disabled until an exact test tenant is authorized for the API allowlist.

1. Choose a dedicated pipeline test agent. Keep the template default Off and change only that agent's Speech caching preference. Use identical provider/model/voice/language/rate settings and the same complete spoken sentences. Use Meet first; test SIP pickup separately with an authorized test number.
2. Collect at least 30 comparable segments for Off, cold On and repeated local On. A new call starts with an empty local cache while sharing is off. Finite and generated speech have distinct identities; compare each path with itself. Generated xAI and expressive/context-dependent speech bypass reuse; native realtime is unsupported.
3. For each completed call record its ID and deployment, provider usage quantities and cache counters. A cold source contributes the SDK's reported usage once. Replay adds no new TTS synthesis usage. Concurrent misses and interrupted/failed requests may still incur provider usage. Compare available provider records for the same window; counters are not an upstream retry or invoice meter. Transport, STT and LLM charges remain separate; unknown models do not establish zero provider cost.
4. Inspect the worker's `tts-cache` aggregate on disposal. Its `cacheWaitMs` and `segmentToFirstFrameMs` contain count/sum/max and disjoint buckets; `boundsMs` identifies their upper limits and the last bucket is overflow. Merge bucket counts to estimate percentile ranges, not exact p95. `cacheWaitMs` includes the combined local-fill/shared deadline and validation; first-frame time includes source construction and scheduling. Provider TTFB uses a different boundary.
5. Measure end of user speech → first audible response on the receiving client separately, using a monotonic client clock or a consented local recording. Include LLM/input/network/playout latency in that measurement; server frame timing cannot substitute. Keep test conditions consistent and record interruption and pickup separately. Do not upload speech/audio or alignment into deployment logs.
6. Acceptance: cache waiting respects the 25 ms budget plus measured event-loop scheduling overhead; cold end-to-end p95 increases by at most 50 ms relative to Off. Stop expansion if accounting duplicates/misses actual synthesis, interruptibility regresses, or these latency targets fail. Small noisy samples are inconclusive and require another controlled sample.
7. Interrupt speech, repeat it, then change voice/rate/model and repeat. Partial captures and changed identities must miss. Confirm native realtime keeps the saved selection while bypassing caching. Switching the agent Off affects new local runtimes; live shared access is revoked immediately by API policy.
8. After separate authorization of a test tenant, enable shared flags on API/worker and add only its UUID to the API allowlist. In a second call verify shared replay, then use a separate tenant to verify denial/no reuse. Verify cleanup, expiry, database load, saturation and publication drops before requesting any customer expansion.

Rollback leaves shared flags false and the allowlist empty. Disable test-agent preference for new local runtimes if needed; retain compatible workers, schema, clips and expiry cleanup. Erflow synchronization is explicitly deferred for this release and remains outstanding.
